Your turn

The art and science of prompting

A good prompt has four ingredients — Goal, Context, Source and Expectations. Select an ingredient to isolate it, then build a real prompt one piece at a time and watch the request sharpen.

Goal
What do you want Copilot to produce?
"Draft an email updating my team…"
Context
Why do you need it, and who is it for?
"…some of them were away this week."
Source
Which information should Copilot use?
"Use our Teams chat and Monday's meeting notes."
Expectations
How should the answer look and sound?
"Under 200 words, friendly, asks as bullets."

Build the prompt, one ingredient at a time

Select the buttons in order. The same request becomes progressively more precise.

Select "+ Goal" to begin building the prompt. Draft an email that updates my team on where our project stands this week. A few of them were away, so they need the short version — what moved forward, what is stuck, and what I need from them. Use our project chat in Teams and my notes from Monday's meeting. Keep it under 200 words in a friendly tone, and put the asks in a short bullet list at the end.

You bring the context

Copilot reasons over the open web and the files you hand it. Every prompt starts with you finding, attaching or pasting the material first.

    Open Copilot and follow along

    Try it yourself

    Each prompt does three things at once — it asks Copilot to explain a concept, applies it to your own file with a / reference, and names the output you want back. That is how you learn a method and finish the work in the same breath.

    A Word document

    Learn what a good project brief contains — and get one written at the same time.
    Try this"What makes a strong project brief? Apply it to /Kickoff Deck.pptx and give me the result as a Word document."

    An Excel workbook

    Learn the standard shape of a risk register, then have yours built from real data.
    Try this"What fields belong in a risk register? Fill one from /Project Tracker.xlsx and put it in a spreadsheet, one row per risk."

    A PowerPoint deck

    Learn how a five-minute update should be structured, then see it applied to your material.
    Try this"How should a five-minute update be structured? Use /Team Update.docx and build it as a five-slide deck."

    When a prompt is not enough

    Stop re-typing it.
    Build an agent.

    The rule of thumb: prompt it once, build it the third time — especially when someone else on your team needs to run it too. An agent is just your prompt, saved as instructions, so it works the same way every time.

    The case: a report compiler

    Every month, the same job — five or six files come in from different people, and someone has to turn them into one report with the same sections, in the same order, every time.

    Prompting it, every month

    You carry the structure in your head

    1. Find the six files again.
    2. Attach them.
    3. Re-type the structure — sections, order, tone, length.
    4. Fix what came back, because you forgot one instruction.
    5. Next month, your colleague does it differently.
    Five steps · a different result each time
    With the agent

    The structure lives in the agent

    1. Open the agent.
    2. Attach this month's files.
    3. Ask for the report as a Word document.
    Three steps · the same structure, every month, for everyone you share it with
    ‹ Agent Builder › New Agent ConfigurePreview Create
    Report CompilerCompiles the files you attach into one structured monthly report
    Instructions

    You are a report compiler. Read every file the user attaches and produce a single monthly report.

    Always use exactly these sections, in this order:
    1. Summary — no more than five sentences
    2. Progress this month — grouped by workstream
    3. Risks and issues — separate the two, name an owner for each
    4. Decisions needed — as a numbered list
    5. Next month

    Cite which file each point came from. If a section has nothing in the attached files, write "Nothing reported" — never fill the gap yourself.

    When the user asks for a document, produce it as a Word file.
